### `_blob_new`

> **seal__blob_new**(n: int) -> string

Allocates an owned binary buffer of `n` zero bytes.
Motivo
The streaming digest states and the HMAC key schedules need a mutable buffer
with an exact byte length; `pengu_string_from_cstr` cannot express embedded
NULs and stops at the first one.
Memoria

with `banish`.


### `_concat_parts`

> **seal__concat_parts**(parts: list of string) -> string

Concatenates the pieces of `parts` in order into one fresh string.
Motivo
The PenguScript spelling of a linear join (`out = "{out}{p}"`) is quadratic,
and `std.scrolls.join` is implemented the same way. This block sums the
lengths, allocates once and `memcpy`s each piece, so the cost is linear and
binary-safe.
Memoria
Allocates one owned buffer of the exact concatenated length; the caller
releases it with `banish`. The input list is only read.


### `_sha2_op`

> **seal__sha2_op**(op: int, alg: int, state: ref to string, data: string, out: ref to string) -> int

Digest engine for the SHA-2 family (and MD5/SHA-1).
Motivo
mbedTLS ships the four contexts already linked into the runtime archive, but
the one-shot bridges only expose hex digests. This block adds the streaming
API, the raw digest bytes (needed by HMAC and PBKDF2) and 64 KiB file
streaming, reusing the same contexts.
Memoria
`state` must point at an owned buffer of at least `HASH_STATE_BYTES` bytes;
it is mutated in place. `out` receives an owned hex or binary string on the
finalising opcodes. File hashing allocates one 64 KiB read buffer.
Precondiciones
An unknown `alg` returns status `1` and writes nothing.


### `_sha3_op`

> **seal__sha3_op**(op: int, alg: int, state: ref to string, data: string, out: ref to string) -> int

Digest engine for SHA3-224/256/384/512.
Motivo
mbedTLS's SHA-3 source is not compiled into the runtime archive (the build
only links md5/sha1/sha256/sha512), so the Keccak-f[1600] permutation is
embedded here. It powers the one-shot digests, the streaming API and 64 KiB
file hashing.
Memoria

is mutated in place; `out` receives the owned hex or binary result. File
hashing allocates one 64 KiB read buffer.


### `_blake2_op`

> **seal__blake2_op**(op: int, alg: int, state: ref to string, data: string, out: ref to string) -> int

Digest engine for BLAKE2b and BLAKE2s.
Motivo
mbedTLS does not ship BLAKE2 at all, so both the 64-bit and the 32-bit

### `_salsa20_8`

> **seal__salsa20_8**(block: string) -> string

Applies the Salsa20/8 core to one 64-byte block.
Motivo
scrypt's ROMix is built on Salsa20/8 over little-endian 32-bit words; the
rotation-and-add schedule is exactly the kind of fixed-width, overflow-wrapped

Precondiciones
`block` must be at least 64 bytes; a shorter block yields `""`.

### `_random_bytes`

> **seal__random_bytes**(n: int) -> string

Returns `n` cryptographically secure random bytes.
Motivo
The module must not depend on `std.lot`: its generator is the C `rand()` PRNG,
which chunk 6 documents as *not* cryptographically secure. This block reads
the operating system's CSPRNG instead (`/dev/urandom` on POSIX, `rand_s` on
Windows) so `random_bytes` really is secret-grade.
Memoria
Allocates one owned `n`-byte string; release it with `banish`.
Precondiciones
Fails closed: an unreadable entropy source returns `""` rather than weak
bytes. `n <= 0` yields `""`.
